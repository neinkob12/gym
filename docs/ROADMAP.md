# Roadmap

Etappen bis zur ersten TestFlight-Version. Jede Etappe endet mit etwas, das du am Handy ausprobieren kannst.

| # | Etappe | Ergebnis am Handy |
| --- | --- | --- |
| E0 | **Planung** (jetzt) | Stil-Prototyp, dieses Doku-Paket |
| E1 | Fundament | Vite + Phaser + TypeScript, Vercel-Deploy, Checks (Typen, Lint, Tests), Karte mit Kamera, Asset-Pipeline für Pixel Art |
| E2 | Kern-Simulation | Kunden kommen, checken ein, trainieren, gehen. Pfadfindung, Verschleiß, Dreck, Geld, Ruf, Tag/Nacht 24/7 |
| E3 | Ranz-Start + Tutorial | geerbtes Gym, Josef führt durch, Aufräumen und Reparieren per Tippen |
| E4 | Bauen | Bau-Modus im Raster, Geräte-Katalog, Deko mit Ambiente, Bereiche freischalten, Level |
| E5 | Personal | Katalog-Menü, Rollen, Gehälter, Werte, Sprüche, Techniker auf Abruf |
| E6 | Protein Bar und Kursraum | Lager, Barista-Verkauf, Trainer im Kursraum |
| E7 | Handy-App | Capacitor, Codemagic, **erste TestFlight-Version**, Haptik, Sound |
| E8 | Meta | Offline-Einnahmen, Tagesaufgaben, Login-Belohnung, Meilensteine, Statistik mit Trainingsplänen und Stammkunden, Bewertungen |
| E9 | Wellness und Ereignisse | Sauna, Pool, Massage; Promi-Tag, Stromausfall, Kunden-Drama |
| E10 | Monetarisierung im Test | Rewarded Ads und In-App-Käufe in der Testversion, Balancing |
| E11 | Store | Android interne Tests, Store-Einträge, Release |

## Nächste konkrete Schritte

1. Stil entscheiden: Modern oder Neon (oder Mischung).
2. Charakter-Runde beantworten (`OFFENE_FRAGEN.md`).
3. Apple Developer Account beantragen.
4. Dann E1 starten.
